# dsh-filemanager — панель дерева файлов воркспейса (дизайн)

Дата: 2026-08-21. Статус: утверждённый дизайн (brainstorming, архитектурный путь).

## Цель

Плагин для DeepSeek Harness Web GUI: кнопка-«язычок» у правого края
сайдбара, по клику слева выезжает панель (визуально похожая на сайдбар)
с деревом каталогов и файлов воркспейса текущей сессии. Только просмотр
структуры: клик по файлу ничего не делает, содержимое не читается и не
редактируется.

Одновременно из web-профиля удаляется установленный ранее плагин
`dsh-file-explorer@0.1.1` (сырой и неудобный; частично дублирует
функциональность).

## Ключевые решения (ответы пользователя)

1. Новый плагин с нуля в `/Volumes/Maxon/dsh-default/dsh-filemanager-plugin`; старый `dsh-file-explorer` удалить из профиля.
2. Клик по файлу — ничего (чистый просмотрщик дерева).
3. Кнопка — плавающий «язычок» на границе сайдбара (слот `shell.overlay`), не в футере сайдбара.
4. Актуальность: ленивая подгрузка при раскрытии + кнопка ↻; без поллинга и file-watcher'ов.
5. Состав: прячем только `node_modules` и `.git`; dotfiles показываем.

## Архитектура

Один npm-пакет `dsh-filemanager` с двумя половинами (канонический
паттерн DSH-плагина, как у `dsh-file-explorer` и родных плагинов):

- **Host-половина** (`lib/index.js`, entry `main`): регистрирует
  read-only HTTP API `/filemanager-fs` через сервис `webServer`
  (`ctx.inject(['webServer'], httpCtx => httpCtx.effect(() =>
  httpCtx.webServer.register({ kind: 'prefix', path: '/filemanager-fs',
  handler }), '...'))`). Эффект с диспоузером — выгрузка плагина снимает маршрут.
- **Client-половина** (`lib/client.js`, export `./client`, манифест
  `dsh.client` в package.json): две регистрации в слот `shell.overlay`
  (list, root) — язычок и панель. React 18 — peer-зависимость.

Отвергнутые варианты: client-only поверх чужого API (публичного
list-directory API у DSH Web нет, а `/hok-fs` уходит вместе со старым
плагином); два отдельных пакета (лишние сущности).

## UI и поведение

### Кнопка-«язычок» (`shell.overlay`, id `filemanager-toggle`)

- Вертикальный таб ~24×64px (иконка/шеврон), `position: fixed`,
  `left` = живая ширина колонки сайдбара, по вертикали ~треть высоты окна.
- Ширина сайдбара отслеживается **ResizeObserver'ом по DOM**: имена
  CSS-классов шелла хэшированные, поэтому колонка ищется структурно —
  наш узел рендерится в слое оверлея грид-фрейма; берём родителя-фрейм
  и его первую дочернюю колонку. Не нашли — деградация к `left: 0`.
- Слой оверлея click-through; кнопка включает `pointer-events: auto`.
- Клик — toggle панели. При открытой панели язычок прижат к её правому
  краю («ручка на выдвинутом ящике»). Переезд — CSS transition.

### Панель (`shell.overlay`, id `filemanager-panel`)

- Выезжает слева, вплотную к сайдбару, поверх центральной колонки
  (контент не сдвигается). Ширина 300px, высота 100%.
- Анимация transform/translateX ~200ms.
- Стили — только токены темы DSH (`var(--dsw-…)`), тёмная/светлая темы
  работают автоматически. CSS инжектится строкой в `<style data-plugin-css>`.
- Состояние `{ open }` — в слотовом сторе с persist (переживает reload);
  экшены `toggle`/`close` — единственный способ записи. Стор объявлен на
  записи язычка, панель использует тот же shared handle.

### Дерево

- Шапка: имя корневой папки воркспейса + ↻ (полный сброс кэша и
  перечитка раскрытых уровней) + ✕ (закрыть).
- Сортировка на клиенте: папки сначала, затем файлы, алфавитно
  case-insensitive.
- Папка: клик — раскрыть/свернуть; первое раскрытие — ленивый запрос
  `list` со спиннером. Файл: инертная строка.
- Иконки: ▸/▾ у папок, цветная точка-маркер по расширению у файлов.
  Без библиотек иконок.
- Путь воркспейса текущей сессии берётся из стандартных хуков
  `useSessions`/`useWorkspaces` (GlobalStandardProps — доступны каждому
  слот-компоненту) и передаётся API как `hint`.
  Смена сессии/воркспейса — полный сброс и загрузка нового корня.
  Нет сессии/воркспейса — пустое состояние («Нет воркспейса»).
- Состояние дерева (раскрытые узлы, кэш, спиннеры) — эфемерный
  React-state панели (по дизайну сбрасывается при ↻ и смене воркспейса).

## Host API

Префикс `/filemanager-fs`, только GET, только чтение.

| Действие | Запрос | Ответ |
|---|---|---|
| root | `GET /filemanager-fs/root?hint=<путь>` | `{ root, name }` — канонический корень и basename |
| list | `GET /filemanager-fs/list?hint=<корень>&path=<отн.>` | `{ entries: [{ name, kind, size? }], truncated? }` |

- `kind`: `dir` / `file` / `symlink-dir` / `symlink-file`.
- `node_modules` и `.git` фильтруются на сервере; dotfiles отдаются.
- `hint` — путь воркспейса от клиента; принимается только существующая
  директория, иначе фолбэк `DSH_WORKSPACE`/cwd. (Модель старого плагина:
  сервер loopback-локальный, воркспейсы сессий — разные папки.)
- Безопасность: обязательный заголовок `x-dsh-filemanager: 1` (иначе
  403); контейнмент через realpath + isInside — целевой путь после
  realpath обязан лежать в корне; симлинк наружу помечается kind'ом,
  но его содержимое не отдаётся (list по нему — 403).
- Папки >2000 записей обрезаются, `truncated: true`; клиент показывает «…ещё N».
- Ошибки: JSON `{ error }`; 403 (заголовок/escape), 404 (ENOENT),
  400 (не директория), 500 (прочее). Хендлер целиком в try/catch —
  сервер DSH не падает.

## Установка и удаление старого плагина

Порядок:
1. Удалить `dsh-file-explorer`: `dsh plugin --profile web remove
   dsh-file-explorer` (или правка `~/.dsh/profiles/web/package.json` +
   переустановка зависимостей профиля) и удаление блока `insert`
   (id `file-explorer`) из `~/.dsh/profiles/web/cordis.patch.yml`.
2. Собрать плагин: `npm install && npm run build`.
3. `dsh plugin --profile web add /Volumes/Maxon/dsh-default/dsh-filemanager-plugin`
   (link-зависимость, как у dsh-superpowers-command).
4. В `cordis.patch.yml` добавить:
   ```yaml
   # dsh-filemanager: панель дерева файлов воркспейса (кнопка у сайдбара)
   - insert:
       - id: filemanager
         name: 'dsh-filemanager'
   ```
5. Пользователь перезапускает `dsh web`; проверка на существующем
   http://127.0.0.1:3080 после refresh. Агент замещающий сервер не поднимает.

Откат: `dsh plugin --profile web remove dsh-filemanager` + удаление блока
из patch-файла; старый плагин возвращается симметрично.

## Обработка ошибок (клиент)

- Ошибка list одной папки — строка «⚠ не удалось прочитать» внутри узла,
  клик — повтор; остальное дерево живо.
- Ошибка root — состояние всей панели с кнопкой «Повторить».
- Краш регистранта изолируется слотовым error boundary (abdication) —
  защитный слой, до которого не доводим.

   обе темы выглядят прилично; старая панель dsh-file-explorer исчезла.
