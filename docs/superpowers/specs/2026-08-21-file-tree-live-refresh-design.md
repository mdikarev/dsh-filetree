# Автообновление дерева каталогов через SSE — дизайн

Дата: 2026-08-21. Статус: утверждённый дизайн.

## Цель

Автоматически отражать изменения на диске в дереве файлов текущего workspace без постоянного ручного нажатия ↻, сохраняя текущие раскрытые узлы и состояние предпросмотра.

## Принятые решения

- Для доставки событий используется SSE; двусторонний WebSocket не нужен, так как поток идёт только от host к клиенту.
- Источник событий — серверный `fs.watch`.
- Наблюдаются только раскрытые каталоги, переданные клиентом.
- События нормализуются, объединяются debounce-окном 200–300 мс и обрабатываются как invalidation.
- Изменение текущего preview-файла не применяется молча: показывается confirmation banner с действиями «Обновить» и «Оставить текущую версию».
- Если `fs.watch` или SSE недоступны, используется polling раскрытых каталогов раз в 5 секунд.
- Изменения в закрытых каталогах не инициируют фоновые запросы; они обнаруживаются при раскрытии каталога или ручном refresh.

## Архитектура

### Host-side watcher

FS API получает новый SSE endpoint:

`GET /filemanager-fs/events?hint=<workspace>&paths=<encoded-json-array>`

Каждый путь в `paths` — относительный путь раскрытого каталога. Сервер проверяет workspace и каждый путь через `realpath` и `isInside`, создаёт watcher только после успешной проверки и освобождает его при закрытии SSE-соединения.

Событие передаётся в нормализованном виде:

`{ "type": "changed", "path": "src/Panel.tsx", "kind": "rename" | "change" }`

События за пределами workspace, из `.git` и из неразрешённых путей не отправляются. Disconnect клиента закрывает все watcher-ы, относящиеся к этому соединению.

### Client-side coordinator

Клиент передаёт серверу список раскрытых путей из store и перестраивает подписку при изменении workspace или набора раскрытых каталогов. Старое соединение закрывается до создания нового.

SSE-событие не является готовым diff. Coordinator:

1. проверяет identity текущего workspace;
2. добавляет путь в debounce-буфер;
3. определяет затронутые раскрытые каталоги;
4. повторно вызывает `fetchList` только для этих каталогов;
5. обновляет Git-статусы, сохраняя expanded paths и preview state.

Создание, удаление или rename обновляет список родительского раскрытого каталога. Изменение файла обновляет его родительский каталог. Если точное сопоставление невозможно, coordinator безопасно обновляет корень и раскрытые узлы.

### Preview behavior

Если событие затрагивает текущий открытый preview-файл, загруженное содержимое остаётся неизменным. В панели появляется уведомление «Файл изменён на диске» с кнопками «Обновить» и «Оставить текущую версию».

«Обновить» повторяет `fetchFile` и очищает уведомление после успешной загрузки. Ошибка чтения остаётся в текущей preview-модели. «Оставить текущую версию» скрывает уведомление до следующего изменения. Для Markdown сохраняется выбранный режим source/rendered.

### Polling fallback

При ошибке запуска SSE или watcher coordinator переходит в polling для раскрытых каталогов с интервалом 5 секунд. Snapshot состоит из имён, типов, размеров и времени изменения доступных записей. Изменение snapshot использует тот же invalidation coordinator.

Polling и SSE останавливаются при закрытии панели, смене workspace или успешном восстановлении SSE. Reconnect SSE выполняется с backoff и не допускает дублирования watcher-ов.

## Public interface

Новый endpoint сохраняет существующий security header `x-dsh-filemanager: 1`. Параметры:

- `hint`: путь текущего workspace;
- `paths`: JSON-массив относительных путей раскрытых каталогов.

SSE payload использует `event: changed` и JSON data с полями `type`, `path`, `kind`. Обрыв соединения не считается ошибкой данных; клиент переподключается или включает polling fallback.

## Failure modes

- Некорректный `hint` или путь за пределами workspace — SSE не создаётся, клиент показывает состояние недоступности автообновления.
- Каталог удалён во время watcher operation — событие обрабатывается без падения, узел исчезает после invalidation.
- Ошибка fetchList — сохраняется последнее состояние узла и используется существующая ошибка загрузки.
- Ошибка watcher-а или SSE — включается polling раскрытых каталогов.
- Смена workspace — старые SSE, watcher-ы и polling останавливаются; создаётся контур нового workspace.
- Несколько быстрых событий — объединяются по пути и дают один refresh.

## Testing and success criteria

Серверные тесты проверяют header, workspace boundary, paths, SSE payload, watcher cleanup и отсутствие событий за пределами workspace.

Клиентские тесты проверяют URL подписки, reconnect/backoff, debounce, targeted invalidation, сохранение expanded paths, confirmation banner, explicit refresh/dismiss, workspace switching и polling snapshot fallback.

Успех наблюдаем, если раскрытый каталог отражает создание/удаление/rename после debounce, закрытые каталоги не опрашиваются, изменённый preview ждёт подтверждения, соединение восстанавливается после сбоя, polling работает как fallback, а ручной ↻ продолжает работать.

## Out of scope

- Двусторонние WebSocket-команды.
- Наблюдение всего workspace при закрытых каталогах.
- Редактирование файлов и автоматическое принятие изменений в preview.
- File watcher для внешних workspace или путей за пределами корня.
