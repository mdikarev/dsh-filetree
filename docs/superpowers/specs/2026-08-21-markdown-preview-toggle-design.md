# Markdown preview toggle — дизайн реализации

Дата: 2026-08-21. Статус: утверждённый дизайн.

## Цель

Добавить в док-панель файлового менеджера переключатель для файлов `.md`: пользователь может читать исходный Markdown или безопасный отрендеренный вид, не покидая текущий контекст DSH Web GUI.

## Решения

- Markdown распознаётся по расширению `.md` без учёта регистра.
- Рендеринг выполняется на клиенте из уже загруженного текста; endpoint `/filemanager-fs/read` не меняется.
- Для рендера используется специализированная Markdown-зависимость с безопасным режимом, а не самописный parser.
- По умолчанию выбран режим «Исходник», чтобы не менять поведение существующего просмотра.
- Режим сохраняется в localStorage отдельно для каждого workspace.
- Относительные ссылки и изображения разрешаются только внутри текущего workspace.
- Внешние текстовые ссылки разрешены и открываются в новой вкладке; внешние изображения автоматически блокируются.
- HTML из исходного Markdown не исполняется; опасные URL-схемы запрещаются.
- Для усечённого содержимого (>5 МБ) предпросмотр остаётся доступен, но показывает предупреждение.

## Архитектура и поток данных

1. Пользователь кликает по файлу в дереве.
2. `Panel` вызывает существующий `fetchFile(hint, path)` и сохраняет исходный текст и флаг `truncated`.
3. Для Markdown-файла в шапке preview-панели появляется переключатель «Исходник / Предпросмотр».
4. Режим «Исходник» использует текущий моноширинный вывод и существующую подсветку.
5. Режим «Предпросмотр» передаёт текст новому чистому модулю renderer-а, который возвращает безопасное представление.
6. Относительные ресурсы разрешаются относительно директории Markdown-файла и проходят workspace boundary; недоступный ресурс не ломает весь документ.
7. При `truncated: true` поверх содержимого показывается заметное предупреждение о частичном просмотре.

## Компоненты и состояние

- `Panel.tsx` хранит `previewMode: "source" | "rendered"` и вычисляет `isMarkdown` по имени файла.
- Новый модуль Markdown renderer-а не зависит от React и принимает имя/путь файла, текст и контекст workspace.
- Переключатель виден только для Markdown-файлов; для остальных файлов DOM и поведение не меняются.
- При смене файла режим берётся из workspace-настройки; для нового workspace используется «Исходник».
- Ошибка renderer-а отображается в preview-панели, при этом пользователь может вернуться к исходному тексту.
- Существующее состояние позиции и размера preview-панели не изменяется.

## Безопасность и ошибки

- Никогда не вставлять необработанный Markdown через `dangerouslySetInnerHTML`.
- Санитизировать результат renderer-а и явно запретить `javascript:`, `data:` и другие опасные схемы для ссылок.
- Внешние изображения не загружать; относительные изображения направлять только через существующий защищённый файловый контур.
- Выход за корень workspace должен деградировать до недоступного ресурса, а не раскрывать содержимое.
- Ошибка чтения файла остаётся текущей ошибкой preview-а; ошибка рендера не должна скрывать исходный текст.
- Усечение не является ошибкой: рендерится доступное начало и показывается предупреждение.

## Тестирование

Покрыть чистой логикой и компонентными проверками:

- распознавание `.md` без учёта регистра;
- переключение и отсутствие переключателя для других расширений;
- раздельное сохранение режима в localStorage по workspace;
- заголовки, списки, ссылки, таблицы и fenced code blocks;
- экранирование HTML и запрет опасных URL-схем;
- разрешение workspace-relative ресурсов и блокировку внешних изображений;
- безопасная деградация при ошибке renderer-а;
- предупреждение для усечённого содержимого;
- отсутствие регрессий в существующих тестах fs API, подсветки и layout.

## Затрагиваемые области

- `src/Panel.tsx` — состояние и UI переключателя.
- Новый чистый модуль Markdown renderer-а.
- `src/styles.ts` — стили rendered Markdown, состояний и предупреждения.
- `package.json` и lockfile — Markdown dependency.
- Новые тесты renderer-а, состояния и безопасности.

Не меняются `src/fs-api.ts` и публичная форма `ReadResponse`, если для workspace-relative ресурсов достаточно существующего защищённого read-контракта.
