# Future Plan: File/folder deletion via tree context menu

## Intent
Первая «мутирующая» операция плагина: удаление файлов и папок из дерева через контекстное меню строки. Сегодня плагин строго read-only (дерево/предпросмотр/live refresh); roadmap сознательно выносил файловые мутации в отдельную фазу с собственным security-дизайном. Удаление — самый необратимый случай мутации, поэтому инициатива фиксирует границы и открытые вопросы до проектирования.

## In scope
- Контекстное меню на строке дерева (правый клик; клавиатурный эквивалент — Menu/Shift+F10), команда «Удалить» с явным подтверждением необратимости
- Предупреждение о потере данных для staged/modified-файлов (git-бейджи уже есть в дереве)
- Серверный write-endpoint удаления: header-гейт `x-dsh-filemanager: 1`; realpath + isInside; файл → unlink; папка → рекурсивное удаление вглубь; symlink удаляется сам, а не цель; удаление корня воркспейса запрещено
- Понятные ошибки (нет файла, занят/нет прав, не пусто) и обновление состояния: live refresh (удалённые узлы исчезают, expanded-пути prune), git-статусы, закрытие/сброс preview удалённого файла
- Локализация строк меню/подтверждения (en/ru) и a11y меню уровня L1

## Out of scope
- Прочие мутации (create/rename/move/copy) — отдельные будущие инициативы
- Корзина, восстановление и undo (см. Open questions)
- Множественное удаление; операции вне воркспейса; `.git` и его содержимое; удаление через OS drag-and-drop

## Absorbs into
- Living canon: Architecture (Public interfaces — write endpoint; Key flows — удаление), Overview (Scope — частичное снятие read-only), Glossary (новые термины меню/удаления)
- Maturity roadmap: фаза мутаций (ранее помечена как требующая собственного security-дизайна)

## Open questions
- Удаление навсегда или в корзину (системная корзина vs служебная папка в воркспейсе)?
- Форма подтверждения: инлайн-диалог плагина vs подтверждение хоста/агента DSH (агент может инициировать удаление случайно)?
- staged/modified-файлы: предупреждение или запрет (потеря незакоммиченных правок)?
- Поведение при удалении открытого preview-файла и раскрытой папки (закрыть preview, prune expanded)?
- Совместимость с trust model (localhost, header-гейт): какие дополнительные гарантии нужны для write-класса операций
- Права ОС (EPERM/EBUSY), файлы, меняющиеся между подтверждением и удалением (race)
